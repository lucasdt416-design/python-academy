## 3. How it works

**The story.** The riddle keeper has a secret number and the player guesses. Lesson 4 says whether the guess is too high, too low or right; lesson 5 whether it is close (no more than 2 away) or out of range (outside 1 to 100); lesson 6 gives points: 10 for exactly right, 5 for close, 1 for within 10, 0 otherwise.

**Each lesson** has the five cards of part 1. Answers are `True`/`False` lines or a number, so wording is never judged and any correct program passes. Support fades: lesson 4's starter asks for both numbers; lesson 5's has two comments; lesson 6's, two shorter ones. Predict-then-run on cards 3 and 4 in every lesson; fix-the-bug as far as five cards allow:
- **Lesson 4:** the predict card is the `>=` boundary question.
- **Lesson 5:** the "Try it" card turns `and` into `or` and asks when the answer changes.
- **Lesson 6:** the "Try it" card turns `elif` into `if` and asks why two lines print.

**The constructs are forced by behaviour, not by a construct rule** (no `require`, no new naming):

| Lesson | The trap | The case that catches it |
| --- | --- | --- |
| `py.boolean-logic` | Joining the "close" limits with `or` is always `True` | A guess 3 away (`just-outside`) |
| `py.boolean-logic` | Joining "out of range" with `and` is always `False` | A guess of 0 (`below-range`) |
| `py.elif` | Separate `if` statements: an exactly right guess is also close and within 10, so it prints three scores (or keeps the last one, 1) | The exact case, visible first (`exact`) |
| `py.elif` | Conditions in the wrong order | The same exact case |

A correct program written with separate `if`s that print one score at the end still passes (it is in "Other ways"): the check judges behaviour, not style.

**Unit complete: the smallest additive way.** A content field, `more_lessons_coming`, on a unit in `catalog.json`. It defaults to `false`, so nothing in the real catalog sets it now that unit 2 is whole. `/api/catalog` adds `complete` = released and not `more_lessons_coming`.

### A.1 `py.compare`: Too high or too low?

Concept: Comparisons · < > <= >= == !=. Description: Compare the player's guess with the riddle keeper's secret number. Badge: **Riddle judge** (`py.badge.riddle-judge`, practice).

| Card | Text |
| --- | --- |
| 1. Discover: Compare two numbers | A comparison asks Python a yes-or-no question about two values. 7 > 5 is True, and 7 < 5 is False. True and False are values too, so print(7 > 5) shows True.<br><br>There are six comparisons: < (less than), > (greater than), <= (less than or equal to), >= (greater than or equal to), == (equal to) and != (not equal to). Two equals signs compare; one equals sign stores a value. 5 <= 5 is True, but 5 < 5 is False. |
| 2. Worked example | `# The lantern needs at least 3 drops of oil` / `oil = 5` / `print(oil >= 3)` / `# Is the tank completely full at 10?` / `print(oil == 10)` / `# Is it empty?` / `print(oil < 1)`<br>Replies: none. ### A.2 `py.boolean-logic`: Close enough?

Concept: Logic · and, or, not. Description: Decide whether a guess is close or out of range by joining comparisons together. Badge: **Close call** (`py.badge.close-call`, practice).

| Card | Text |
| --- | --- |
| 1. Discover: Join two questions into one | and, or and not combine True and False. A and B is True only when both are True. A or B is True when at least one of them is True. not flips True to False, and False to True.<br><br>Each side of and or or is a whole comparison: write x > 0 and x < 10, not x > 0 and < 10. Python works out the comparisons first, then not, then and, then or. Use parentheses when you want to be sure of the order. |
| 2. Worked example | `# The bridge is safe for 2 to 6 travellers` / `travellers = 7` / `print(travellers >= 2 and travellers <= 6)` / `# Too few or too many?` / `print(travellers < 2 or travellers > 6)` / `# Flip the first answer with not` / `print(not (travellers >= 2 and travellers <= 6))`<br>Replies: none. Output: `False` / `True` / `True`<br>7 is at least 2 but more than 6, so the and line is False. The or line needs only one side to be True, and 7 > 6 is. not flips the first answer from False to True. |
| 3. Predict | If travellers were 2, what would the first print() show?<br>Options: **True** (answer); False<br>Why: 2 >= 2 is True and 2 <= 6 is True. With and, both sides are True, so the whole line is True. |
| 4. Try it | Try travellers = 2, then 6, then 0, and predict the three lines before each run. Then change and to or in the first print(). Find a number of travellers where the answer changes, and explain why. |

### A.3 `py.elif`: The riddle keeper's verdict

Concept: Decisions · elif. Description: Give points for a guess by how close it is, choosing exactly one branch. Badge: **Fair verdict** (`py.badge.fair-verdict`, practice).

| Card | Text |
| --- | --- |
| 1. Discover: One choice out of many | if and else choose between two paths. elif, short for "else if", adds more. Python checks each condition from the top and runs only the first block whose condition is True. It skips the rest.<br><br>Order matters when conditions overlap. A guess that is exactly right is also close, so check for exactly right first. else catches everything the conditions above it did not. Each elif line ends with a colon, and its block is indented by four spaces. |
| 2.

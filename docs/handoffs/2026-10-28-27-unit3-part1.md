## 3. How it works

**The story continues** from unit 2: the riddle keeper's secret number. Lesson 1 lets the player keep guessing (`while`); lesson 2 gives them only three tries (a loop that stops on time); lesson 3 walks steps with `for` and `range()`. Each lesson has the five cards of units 1 and 2, predict-then-run on cards 3 and 4, and fading support: lesson 1's starter has the two input lines and a comment, lesson 2's only comments, lesson 3's one comment.

| Lesson | Challenge | The traps the cases catch |
| --- | --- | --- |
| `py.while-loops` "Keep guessing" | While the guess is wrong, print `True` (too high) or `False` (too low), then ask again | A loop that never asks again (endless); one that asks once too often (runs out of replies); `if` instead of `while`; a right first guess (prints nothing) |
| `py.loop-termination` "Three tries" | At most three guesses: print how many were used, then whether the last was right | No limit (a fourth guess is read); `<=` for `<` (four tries); stopping one early; counting wrong; extra replies left unread |
| `py.for-range` "Step by step" | Print 2, 4, … up to the number given | `range(2, top)` missing the top when it is even; starting at 0; a top of 1 (prints nothing) |

### The four loop investigations you asked for

1. **Input running out.** A loop that asks for one reply too many raises `EOFError` in Python.
   - **In a check:** the case is `needs_work` with reason `missing_input`: "Your program asked for more replies than this check gives. Check how many times it calls input()." The lesson's tagged `EOFError` hint is offered first, and says what to check in this loop (lesson 1: "Check that it stops as soon as the guess is right").
   - **On Try it:** the page shows the existing "Not enough player replies" message; card 4 of lesson 1 invites this on purpose.
2. **Endless loops.**
   - **In a check:** each case has 3 seconds; the program is stopped, the rest of the cases are not run, and the explanation now reads "…usually because a loop never ends. Check that something inside the loop changes, so that the loop can stop."
   - **On Try it:** a silent endless loop is stopped by the worker's existing 15-second limit, and the page stays usable. A printing one hits the 20,000-character Try it cap almost at once. Lesson 2's Try it (delete `count = count - 1`) is a printing loop, so the learner sees "Too much output" quickly instead of waiting.
3. **The output limit.** 10,000 characters per case in a check (unchanged). A printing endless loop reaches it in well under a second and is reported as `output_limit`. Every expected output in these lessons is under 200 characters (tested). Investigating this found the worker bug in section 5.
4. **Termination off-by-one.** Lesson 2 has two visible cases, `extra-replies` (more replies than tries; checked before `out-of-tries`) and `out-of-tries` (exactly three wrong). Order matters:
   - A loop with **no limit** reads a fourth reply in `extra-replies`, so it prints `4` and `True` instead of `3` and `False`. That is a wrong-output result with a tagged hint about the limit, not a confusing "ran out of replies".
   - A loop that **stops early** (`< 2`) fails `third-try`.
   - A loop that **stops late** (`<= 3`) fails `extra-replies`.
   - Lesson 3's `even-top` and `none` cases catch `range()` stopping one step early or running when it should not.

**Constructs are not forced.** There are no `require` rules. A `for` loop cannot be forced by behaviour (a `while` loop prints the same lines), so lesson 3's "Other ways" shows the `while` version and says why `for` is shorter. Lesson 1 could be written with `while True:` and `break`; that passes too and is in "Other ways".

## Appendix. Every card, hint and check case, word for word

### A.1 `py.while-loops`: Keep guessing

Concept: Loops · while. Description: Let the player keep guessing the secret number until they get it right. Badge: **Patient guesser** (`py.badge.patient-guesser`, practice).

| Card | Text |
| --- | --- |
| 1. Discover: Repeat while something is true | A while loop repeats a block of code for as long as its condition is True. Python checks the condition, runs the indented block, then checks again. When the condition becomes False, the loop ends and the program carries on below it.<br><br>Something inside the loop must change, or the condition stays True forever. To keep asking the player, call input() once before the loop and again at the end of the block. If the condition is False the very first time, the block never runs at all. |
| 2. Worked example | `# Keep asking until the password is moon` / `word = input("Password? ")` / `while word != "moon":` / `    print("The door stays shut.")` / `    word = input("Password? ")` / `print("The door opens.")`<br>Replies: Reply 1: 'star', Reply 2: 'sun', Reply 3: 'moon'. Output: `The door stays shut.` / `The door stays shut.` / `The door opens.`<br>The condition is checked before each repeat. star and sun are not moon, so the block runs twice. When word becomes moon, the condition is False, the loop ends, and the last line runs. |
| 3. Predict | If the first reply were moon, what would the program print?<br>Options: **Only The door opens.** (answer); The door stays shut. once, then The door opens.; Nothing at all<br>Why: word != "moon" is False straight away, so the block never runs. Python goes on to the last line and prints The door opens. |
| 4. Try it | Run it, then change the replies so that moon comes first, then last. Predict how many times The door stays shut. appears before each run. Then try three wrong replies and read what happens when the replies run out. |
| 5. Challenge | The riddle keeper lets the player keep guessing. The starter asks for the secret number and the first guess. While the guess is wrong, print True if it is too high or False if it is too low, then ask for another guess. When the guess is right, the loop ends. Print just the True and False lines. The check tries several runs of guesses, including some you can't see.<br>Starter: `# These two lines ask for the secret number and the first guess` / `secret = int(input("Secret number? "))` / `guess = int(input("Your guess? "))` / `# While the guess is wrong: print whether it is too high, then ask again` |

| Hint | Text |
| --- | --- |
| A nudge | You need a loop that repeats while the guess is not the secret. Inside it, two things happen: a print() and a new guess. |
| A bigger hint | Look at the comment. The loop's condition compares guess with secret using !=. The last line inside the loop asks for the next guess, the same way the starter asked for the first one. |
| The approach | A pattern from the worked example: while word != "moon": with an indented print(), then an indented line that asks again. Your loop compares numbers instead of words. |
| About `EOFError` | Your loop asked for another guess after the last reply. Check that it stops as soon as the guess is right: that is when its condition should become False. |
| About `NameError` | Use the names from the starter, secret and guess, and spell them the same inside the loop. |
| About `IndentationError` | The lines inside the loop start with four spaces, so Python knows they belong to it. |
| About `TypeError` | Each new guess needs int(...) too, like the first one. Python can't compare text with a number using >. |
| About `py.while-loops.case.three-tries` | With a secret of 7 and guesses of 9, 3 and 7, the lines are True, then False. If only True printed, your program checked once with if; a while loop checks again after every guess. |
| About `py.while-loops.case.first-try` | When the first guess is right, the loop never runs and nothing is printed. If your program printed a line, check that the print() is inside the loop. |
| About `py.while-loops.case.many-low` | Three low guesses print three False lines. Make sure your loop keeps going for as long as the guess is wrong, however many guesses that takes. |
| About `py.while-loops.case.below-zero` | Guesses below zero compare the same way. Compare guess with secret, not with particular numbers. |
| About `py.while-loops.case.long` | Your loop needs to keep going for as many wrong guesses as the player makes, not for a fixed number of them. |
| Similar example | `steps = 1` / `while steps < 50:` / `    steps = steps * 3` / `print(steps)`<br>The loop keeps tripling steps while it is under 50: 1, 3, 9, 27, then 81. 81 < 50 is False, so the loop stops and 81 is printed. Your challenge repeats while a guess is wrong, and asks for a new guess each time. |
| Other way, after passing | `secret = int(input("Secret number? "))` / `guess = int(input("Your guess? "))` / `while guess != secret:` / `    too_high = guess > secret` / `    print(too_high)` / `    guess = int(input("Your guess? "))`<br>Keep the answer in a variable, then print it. |
| Other way, after passing | `secret = int(input("Secret number? "))` / `while True:` / `    guess = int(input("Your guess? "))` / `    if guess == secret:` / `        break` / `    print(guess > secret)`<br>while True repeats until break leaves the loop, so input() is written only once. The next lesson looks at how loops end. |

| Case | Visibility | Description (shown to learners) | Replies | Expected output |
| --- | --- | --- | --- | --- |
| `three-tries` | visible | a secret of 7 and guesses of 9, 3 and 7 | '7', '9', '3', '7' | `True` / `False` |
| `first-try` | visible | a secret of 5, guessed first time | '5', '5' | (nothing) |

### A.3 `py.for-range`: Step by step

Concept: Loops · for and range(). Description: Count the steps of a staircase with a for loop and range(), two at a time. Badge: **Step counter** (`py.badge.step-counter`, practice).

| Card | Text |

| 1. Discover: Count with for and range() | A for loop runs its block once for each value it is given. range(1, 4) gives 1, 2 and 3: it starts at the first number and stops before the second.
